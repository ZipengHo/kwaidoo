# GPF 微服务专题摘要

## 任务边界

- 以 TinyService 微服务为交付物
- 常见主题包括服务接口、路由、追踪、钩子、跨服务调用和排障

## 关键模式

- 先明确服务边界、调用方和被调用方
- 接口契约应先于实现细节稳定下来
- 微服务接口和实现的组织方式仍应沿用普通 Cell 的基础接口/实现分层规范，而不是绕开接口直接堆静态工具调用
- 微服务接口不支持服务 Cell 建模，不能引入服务 Cell 生命周期和相关基类
- 微服务接口虽然本质上是普通 Cell 风格接口，但契约类型必须与具体代理工程解耦
- 接口入参与返回值优先选基础类型、基础集合和可序列化的贫血 POJO，避免把富业务对象或代理私有类型暴露到微服务边界上
- 路由、追踪和钩子属于框架层能力，需要说明启用位置和作用点
- 跨服务调用要说明超时、失败传播和降级策略

## 典型故障

- 没有按普通 Cell 规范拆分接口和实现，导致微服务边界与实现边界混乱
- 把微服务接口误写成服务 Cell，错误引入 `ServiceCellIntf`、`BasicServiceCell` 或生命周期方法
- 接口参数或返回值依赖某个代理私有工程类型，导致无法稳定下发或跨代理调用
- DTO/POJO 没有满足序列化要求，导致远程调用传输失败
- 路由配置不匹配导致服务不可达
- 跨服务调用失败但未暴露可观测信息
- 钩子或追踪接入不完整导致排障困难
