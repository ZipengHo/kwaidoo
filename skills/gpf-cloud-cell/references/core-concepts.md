# GPF 云开发 Cell 核心概念

## 工厂与获取方式

- 普通 Cell：可通过 `Cells.get()` 获取，也可直接创建；需要远程联调时优先通过工厂
- 服务 Cell：必须通过工厂获取，由框架管理生命周期
- 资源 Cell：通常直接创建或由其他 Cell 包裹构建，不应按普通服务那样托管

补充约束：

- 资源 Cell 不应通过 `Cells.get()` 获取
- 需要工厂托管并支持联调的接口、实现类应放在 `cell.` 开头的包下
- 谁创建资源 Cell，谁负责关闭

## 包结构约束

- Cell 接口和实现类应放在 `cell.` 开头的包下
- DTO、枚举、常量、工具类不应滥放到 `cell.` 包里

## 生命周期

服务 Cell 常见生命周期方法：

- `doStartService()`：启动初始化
- `doStopService()`：释放线程池、缓存、连接等资源

预加载约束：

- 接口实现 `CellPreloadIntf` 后，系统加载或插件发布时会提前触发获取
- 对服务 Cell 来说，这通常意味着更早执行启动逻辑
- 只有确实需要启动即初始化时才使用预加载

## 云配置

- 配置类应与服务 Cell 明确绑定
- 配置值要有默认值
- 输出中应说明本地调试配置、代理机配置和全局配置的优先级

推荐做法：

- 配置类继承 `CellConfig`
- 服务实现类通过 `@Config` 绑定配置类
- 启动时通过 `getConfig()` 读取配置

覆盖顺序：

- Java 默认值
- DAO 全局配置
- 代理机配置
- 开发端调试配置

## 云 UDF

- 包名以 `udf` 开头
- 各 UDF 应独立编译
- 不应把复杂长期状态逻辑放进 UDF

## 常见边界

- 需要持久化状态、线程池、定时任务：优先服务 Cell
- 只是单次计算：优先普通 Cell
- 需要包裹不可序列化资源：优先资源 Cell
- 需要异步结果：优先 `IPromise`，不要使用 `CompletableFuture`
