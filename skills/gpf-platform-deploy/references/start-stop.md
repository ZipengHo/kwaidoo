# 服务启停说明

## 启动脚本

- `startup.sh`
  - 前台启动
  - 直接执行 Java 主程序
  - 适合首次排障、查看实时启动日志

- `nohupStartup.sh`
  - 后台启动
  - 本质上调用 `nohup ./startup.sh > log.txt &`
  - 适合长期运行或服务器后台启动

- `startup_debug.sh`
  - 调试启动
  - 会附加远程调试参数
  - 第一个参数用于调试端口

## 停止服务

默认停止方式：

1. 先根据服务监听端口查找进程
2. 再对对应进程执行 `kill`

常见端口来源：

- HTTP 端口
  - 例如 `jetty.http.port`

- RPC 端口
  - 例如 `crpc` 模块中的 RPC 端口

常见做法：

- 先按 HTTP 端口查
- 如果 HTTP 端口不明确或未启用，再按 RPC 端口查
- 确认 PID 后执行 `kill PID`
- 如果进程无法正常退出，再根据现场要求决定是否使用强制终止

Linux 下常用命令：

```bash
# 按端口查监听进程
ss -ltnp | grep ':8090'

# 或者使用 lsof 按端口查 PID
lsof -i :8090

# 提取 PID 后停止进程
kill PID

# 如果进程未退出，再强制停止
kill -9 PID
```

如果需要直接从端口提取 PID，可使用：

```bash
lsof -t -i :8090
```

如果服务同时暴露 HTTP 端口和 RPC 端口，优先用当前现场最明确的业务端口定位；如果 HTTP 端口查不到，再查 RPC 端口。

适用建议：

- 单 GPF 默认优先按 HTTP 端口或 RPC 端口定位进程
- 后台启动场景停止服务时，也仍然优先按端口查进程，不依赖额外停止脚本

## 使用建议

- 首次部署或启动失败时，优先用前台启动观察报错
- 需要服务器常驻运行时，再切换到后台启动
- 需要远程调试 Java 进程时，使用调试启动脚本
- 停止服务时，优先按端口定位进程并执行 `kill`

## 核心事实

- 启动脚本依赖 `JAVA_HOME`
- 启动脚本会把 `$JAVA_HOME/bin` 加入 `PATH`
- 前台启动脚本会打印 `java -version`
- 后台启动默认把输出写到 `log.txt`

## 常见操作输出

- 检查 JDK 是否正确：看脚本输出中的 `java -version`
- 检查后台是否已启动：看 `log.txt` 是否持续输出，或检查进程是否存在
- 调试启动时确认端口：看脚本拼接出的 `JAVA_DEBUG_PARAM`
- 停止服务时确认目标进程：优先核对端口和 PID 的对应关系
