# init

初始化当前工程的协作说明文件 `AGENTS.md`。

## 工作流

```text
开始
  ↓
读取技能目录内置模板 `references/templates/AGENTS.template.md`
  ↓
在目标工程根目录生成或更新 `AGENTS.md`
  ↓
识别模板中的占位信息与待补全部分
  ↓
分析当前工程的目录结构、构建方式、依赖组织、可用技能和协作约束
  ↓
补全 `AGENTS.md`
  ├─ 填入当前工程真实信息
  ├─ 删除模板提示语和占位文本
  └─ 保留用户已有且不冲突的项目规范
  ↓
输出结果并提示用户复核
```

## 分析要求

- MUST 不再依赖 `init.sh` 或其他初始化脚本，直接以模板为起点生成 `AGENTS.md`。
- MUST 使用当前技能目录内部模板，MUST NOT 引用外部模板路径。
- MUST 仅基于当前工程内可见的目录、源码、配置、脚本和技能清单补全内容，MUST NOT 猜测。
- 对无法确认的信息，MUST 写为“当前工程中未发现”或“需人工确认”，MUST NOT 编造默认结论。
- MUST 先分析当前工程真实内容，再补全模板中的占位信息。
- 最终生成结果 MUST NOT 保留 `[待补全]`、模板说明语、或“按实际情况填写”之类占位文本。
- MUST 仅保留与当前工程直接相关的内容，MUST NOT 写入无关技能、无关规范或通用空话。
- 如果工程根目录已存在 `AGENTS.md`，SHOULD 优先增量更新与 `bapdev-cli`、云工程协作、编译方式相关的区块，而不是整体覆盖。

## 补全重点

- 项目概述：根据当前工程真实情况填写，而不是照搬模板描述。
- 目录结构：根据当前工程实际目录补全。
- 技能入口：不要直接罗列 `bapdev-cli` 子命令，而应说明：
  - 哪些技能可用于 BAP 云工程操作与代码编译
  - 哪些技能可用于代码开发
- 云工程协作规范：说明环境初始化、刷新、差异比较、提交、发布等约束。
- 构建与编译：说明本地编译依赖 `.classpath`、输出目录和依赖同步方式。

## 技能入口补全规则

- BAP 云工程操作与代码编译，应优先归入 `bapdev-cli` 技能能力范围。
- 代码开发相关技能，应按当前工程实际场景补充，例如：
  - HTTP 接口开发技能
  - 规则函数开发技能
  - Java 路由或接口定义技能
- 如果某类开发任务在当前工程里没有对应技能或无法确认，MUST NOT 编造。
