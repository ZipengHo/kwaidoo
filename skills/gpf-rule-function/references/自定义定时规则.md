# 自定义定时规则

## 适用场景

当需求不是“表单/流程规则函数”，而是“定时任务的自定义触发规则”时，使用本方式开发。

这类能力不走 `CellIntf` 体系，而是实现调度框架中的 `cmn.dto.scheduletask.timerule.TimeRule`。

## 核心接口

参考源码：

- 接口定义：`../assets/source/cmn_util/src/core/cmn/dto/scheduletask/timerule/TimeRule.java`
- 加载入口：`../assets/source/cmn_util/src/core/cmn/dto/scheduletask/timerule/TimeRuleUtil.java`
- 开发样例：`../assets/source/cmn_util/src/core/cmn/dto/scheduletask/timerule/UserDefineTimeRuleExample.java`

`TimeRule` 需要实现以下方法：

- `isMatch(Calendar calOptime, boolean isSearchNext)`
- `saveXML()`
- `loadFromXml(Element ele)`
- `getName()`
- `clone()`
- `preLoad(Calendar calOptime, boolean isSearchNext)`
- `isSecondLevel()`

## 开发方式

### 1. 实现接口

- 直接实现 `cmn.dto.scheduletask.timerule.TimeRule`
- 不要错误实现为 `CellIntf`

### 2. 实现匹配逻辑

在 `isMatch(Calendar calOptime, boolean isSearchNext)` 中判断当前时间是否命中规则：

- 命中时返回 `TimeRule.MATCH`
- 不命中时应尽量返回最准确的未匹配层级，而不是统一返回笼统失败

常用返回值包括：

- `TimeRule.YEAR_UNMATCH`
- `TimeRule.MONTH_UNMATCH`
- `TimeRule.DAY_UNMATCH`
- `TimeRule.HOUR_UNMATCH`
- `TimeRule.MINUTE_UNMATCH`
- `TimeRule.SECOND_UNMATCH`
- `TimeRule.OTHER_UNMATCH`

返回值会直接影响调度器如何推进搜索时间：

- `YEAR_UNMATCH`：跳到下一年
- `MONTH_UNMATCH`：跳到下一月
- `DAY_UNMATCH`：跳到下一天
- `HOUR_UNMATCH`：跳到下一小时
- 其他分钟/秒级不匹配：按更细粒度继续推进

因此，返回越精确，调度搜索越高效。

### 3. 区分前后搜索语义

`isSearchNext` 表示当前是在做“向后搜索下一个执行时间”，还是“向前回溯上一个执行时间”。

- `true`：向后搜索
- `false`：向前回溯

边界条件通常需要分别处理，不能简单共用同一套比较逻辑。

### 4. 实现 XML 持久化

在 `saveXML()` 中：

- 创建 `TimeRule.XML_RULE_USER_DEFINE` 节点
- 写入 `TimeRule.RULE_CLASS` 属性
- 如有名称、参数文本、自定义配置，一并写入 XML

在 `loadFromXml(...)` 中：

- 对称恢复 `saveXML()` 写出的字段

### 5. 保证类可反射加载

`TimeRuleUtil.parseXML(...)` 在解析 `Rule_User_Define` 节点时，会：

- 从 XML 读取 `RuleClass`
- 通过 `ClassFactory.getValidClassLoader().loadClass(...)` 加载类
- 反射创建实例

因此自定义规则类必须满足：

- 位于运行时可见的 classpath
- 可被当前类加载器找到
- 具备可实例化条件

### 6. 使用预加载优化性能

调度器在批量搜索未来执行时间前，会调用 `preLoad(...)`。

适合放进 `preLoad(...)` 的内容：

- 数据库查询
- 缓存装载
- 远程配置读取
- 较重的预计算逻辑

目标是避免调度器在逐分钟或逐秒迭代时重复准备相同数据。

### 7. 正确声明时间粒度

`isSecondLevel()` 用于告诉调度器当前规则是否需要秒级搜索：

- 仅分钟及以上粒度：返回 `false`
- 含秒级匹配逻辑：返回 `true`

如果这里声明错误，调度器可能按错误粒度推进，导致匹配结果不正确。

### 8. 实现克隆

推荐做法是仿照样例，通过 `saveXML()` + `loadFromXml(...)` 实现配置级拷贝，保证克隆对象与原对象保持一致。

## 样例说明

样例文件：`../assets/source/cmn_util/src/core/cmn/dto/scheduletask/timerule/UserDefineTimeRuleExample.java`

该样例展示了一个“工作日 9:00-18:00”规则，主要体现：

- 直接实现 `TimeRule`
- 在 `isMatch(...)` 中按年份、月份、日期、星期、小时、分钟逐层判断
- 根据 `isSearchNext` 处理不同方向的边界
- 用 `saveXML()` / `loadFromXml(...)` 保存和恢复名称、参数
- 用 `preLoad(...)` 预留数据准备入口
- 通过 `isSecondLevel()` 声明当前不是秒级规则

## 输出要求

当回答“如何开发自定义定时规则”时，输出中至少应包含：

- 规则用途与触发场景
- `TimeRule` 实现方式
- `isMatch(...)` 的返回值设计
- XML 持久化方式
- 是否秒级、是否需要 `preLoad(...)`
- 运行时类加载前提

## 注意事项

- 不要把自定义定时规则写成 `CellIntf` 规则函数
- 不要遗漏 `RuleClass` 属性，否则 `TimeRuleUtil` 无法反射加载
- 不要在 `isMatch(...)` 中一律返回模糊失败值，否则会显著降低搜索效率
- 如果规则依赖昂贵计算，不要把准备逻辑放在每次匹配判断里
