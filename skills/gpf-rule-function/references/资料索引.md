## 按任务选资料

- 判断规则函数类型：读取 `overview.md`
- 判断该落到哪类规则：读取 `rule-decision-table.md`
- 判断注解、环境变量和字段约束：读取 `core-concepts.md`
- 判断当前场景有哪些环境变量可用：读取 `environment-variables.md`
- 生成代码：读取 `workflow.md` 和 `patterns.md`
- 生成前避免误写：读取 `anti-patterns.md`
- 排错：读取 `errors.md`
- 输出前自检：读取 `checklist.md`
- 需要确认注解、环境变量类型或上下文对象：先读 `源码类索引.md`，再按需读取 `assets/source/`

## 按问题查样例

- 想确认第一个规则函数的最小结构：看 `assets/examples/quick_start_rule.java`
- 想确认最小注解结构怎么写：看 `assets/examples/user_register_rule.java`
- 想确认 `Cnd` 过滤里字段名如何转字段编码：看 `assets/examples/data_filter_rule.java`
- 想确认界面联动时 `Form` 与组件 API 如何混用：看 `assets/examples/frontend_fill_value_rule.java`
- 想确认复杂统计查询如何返回 `ResultSet<Form>`：看 `assets/examples/data_filter_sql_rule.java`
- 想确认自动提交回调如何设置真实回调参数：看 `assets/examples/auto_submit_rule.java`
- 想确认待办通知回调如何校验模板并挂到保存回调：看 `assets/examples/todo_notify_rule.java`
- 想确认身份匹配规则在 `matchUser` 与 `queryUser` 两种模式下如何分别返回 `IdentifyMatchParam` 和 `List<User>`：看 `assets/examples/identity_match_rule.java`
- 想确认动态权限辅助只该做什么：看 `assets/examples/privilege_assign_rule.java`
- 想确认订单类需求如何组合多种规则函数能力：看 `assets/examples/order_rule.java`
- 想确认在一个 CM 服务中如何通过 `NCMDataService` 调用另一个 CM 服务的表单实例化、详情查询、列表查询和表单操作，而不是直接通过 `IFormMgr` 查询和操作表单，也不是通过 `ContextModelMgr` / `executeCmMethod(...)` 手动执行目标 CM 方法：看 `assets/examples/ncm_data_service_rule.java`
- 如果提问类似“编写一个CM服务调用规则，通过当前表单的关联工程属性调用编号为 IML_00004 的CM服务的保存操作”：看 `assets/examples/ncm_data_service_rule.java`，必须生成 `NCMDataService` 调用，不要生成 `ContextModelMgr`、`DriverDto`、`Methods`、`cloneContext(targetCm)`、`executeCmMethod(...)`
