# GPF 基础 API 字段选择决策表

## 目标

当你要写 `Form`、`TableData` 或 `Cnd` 相关代码时，先用这张表判断该用：

- 字段中文名
- 字段编码
- 系统常量

## 决策表

| 场景 | 优先写法 | 典型 API | 说明 |
|------|----------|----------|------|
| 表单业务属性写入 | 字段中文名 | `form.setAttrValue("客户名称", "张三")` | 默认规则，最符合业务语义 |
| 表单业务属性读取 | 字段中文名 | `form.getString("客户名称")` | 默认规则，避免不必要编码转换 |
| 表单系统属性写入 | `Form` 常量 | `form.setAttrValueByCode(Form.Code, "ORDER001")` | 系统属性特例 |
| 表单系统属性读取 | `Form` 常量 | `form.getStringByCode(Form.Code)` | 系统属性特例 |
| 嵌套表业务字段写入 | 字段中文名 | `detail.setAttrValue("数量", 2L)` | 明细业务字段仍按字段名 |
| 嵌套表业务字段读取 | 字段中文名 | `detail.getLong("数量")` | 明细业务字段仍按字段名 |
| 嵌套表系统属性读取 | `TableData` 常量 | `detail.getLongByCode(TableData.OrderSeq)` | 读取主表关系与排序信息 |
| `Cnd` 查询系统属性 | 固定系统字段名 | `Cnd.where("status", "=", 1)` | 系统属性可直接使用 |
| `Cnd` 查询业务属性 | 字段编码 | `Cnd.where(fieldCode, "=", "张三")` | 业务属性进入查询前通常先转编码 |
| 动态字段场景 | 字段编码 | `form.getAttrValueByCode(fieldCode)` | 当前逻辑只有编码，没有稳定字段名 |
| 迁移或特殊修复场景 | 系统常量或编码 | 视具体字段而定 | 这类场景要显式说明原因 |

## 快速判断问题

### 1. 你是在“读写表单值”还是“写查询条件”？

- 读写表单值：先默认字段中文名
- 写查询条件：先判断是不是系统属性，不是就转字段编码

### 2. 你当前字段是不是 `Form` / `TableData` 系统属性？

- 是：用系统常量
- 不是：继续看是不是业务字段

### 3. 你拿到的是不是动态字段编码？

- 是：可以用 `ByCode`
- 否：优先回到字段中文名

## 最短口诀

- 业务读写用字段名
- 系统字段用常量
- 查询条件用编码
- 动态字段才用 `ByCode`
