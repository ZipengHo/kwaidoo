# GPF 基础 API 核心概念

## 真实管理器接口

- `cell.gpf.adur.user.IUserMgr`
- `cell.gpf.adur.role.IRoleMgr`
- `cell.gpf.adur.data.IFormMgr`

不要发明不存在的接口名。

## 模型与字段

- 表单和用户等对象通常都依赖模型 ID
- 字段读写要区分“业务属性读写”和“编码驱动场景”
- 表单取值时应注意数据类型：字符串、布尔、长整型、附件、关联数据等

### 业务属性读写默认规则

- 对业务场景定义的属性，默认优先使用 `setXXX` / `getXXX`
- 只有在系统属性、动态字段名、查询条件构造、字段已被明确转换为编码时，才优先考虑 `ByCode`
- `Form` 与 `TableData` 的系统属性清单见 `system-fields.md`

### 什么时候用 `ByCode`

- 构建 `Cnd` 条件，且当前字段必须先转换为编码
- 处理 `Form` / `TableData` 的系统常量字段
- 当前逻辑拿到的是动态字段编码，而不是稳定的业务字段名

## 事务

- 修改类操作通常需要显式提交事务
- 查询和修改不要混成一个黑盒逻辑，输出中要交代事务边界

## 查询分页

- 条件查询一般用 `Cnd`
- 列表返回一般配合 `ResultSet`
- 输出要说明分页参数和结果结构
